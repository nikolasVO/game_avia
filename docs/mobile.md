# Native build and test preparation

Pinned Godot **4.7.2.stable.official.ed1daf0bf**, standard GDScript build and exact 4.7.2 export templates. No C#, GDExtension or third-party game plugin. Mac: Intel, macOS 15.7.8, Radeon Pro 560X. Compatibility is provisional. Same procedural scene rendered in Compatibility/OpenGL 4.1 and Mobile/Vulkan 1.2.334; real-phone renderer choice remains NOT VERIFIED.

Android setup actually used: Temurin OpenJDK 17.0.21+9, SDK Platform 36 rev2, Build-tools 36.1.0, platform-tools, engine templates' precompiled native libraries. The template's `config.gradle` is the installed-version source of truth: target/compile 36, min 24, AGP 8.6.1, Gradle 8.11.1, Kotlin 2.1.21, native build version NDK 29.0.14206865. No NDK build was needed; no native plugin was added. The initial docs-recommended tools 35.0.1 could package the prebuilt APK, but Gradle export now uses the actual template's matching tools. No `sdkmanager --licenses`, account agreement or purchase was performed.

`tools/build_game.py --godot <binary> --target apk|aab|server|mac --out builds` verifies the exact engine, imports from source, runs a finite export and writes artifact hash/source SHA/dirty/signature/device-test metadata. Android paths/debug key are configured in the user's Godot editor settings outside Git. AAB template installation is automatic only for an explicit manual AAB build. Generated Android/Gradle files and signing keys stay outside Git. AAB is an actual unsigned release bundle; it is not eligible for Play upload without release signing. Debug APK uses an ordinary development keystore.

Package ID `com.nikolasvo.gameavia`, versionName 0.1.0, versionCode 1; landscape, ARM64 + x86_64. Static APK verification covers signature schemes, ELF PT_LOAD 16 KB alignment and ZIP alignment. AAB validation uses official bundletool 1.18.3 (SHA256 checked). None substitutes for runtime on a 16 KB device. APK/resources are below the project's 300 MB starting budget.

Actual Android runtime test environment: Android Emulator **37.2.13.0**, AOSP API35 x86_64 rev2, 1280×720, SwiftShader/ANGLE on Mac. This is an emulator, not a physical mid-range phone. APK installed and displayed the native menu/world; it joined a separate server alongside a desktop client using ENet/DTLS and rendered the other aircraft. Evidence and exact artifact versions are in `docs/evidence/`. The menu overflow discovered by this test was fixed. ADB video capture interrupted by an editor's ADB shutdown is a failed capture attempt; only a subsequently verified complete recording may be labelled accepted.

Full Xcode, iOS SDK, Team ID, provisioning, signing and physical iPhone are absent. Real `xcodebuild -version` failed because only CommandLineTools is selected. Real `--export-debug 'iOS Test'` rejected missing App Store Team ID. There is **no exported Xcode project, built IPA or TestFlight archive**. A preset does not close this gate. Do not use a fabricated Team ID to make an export appear complete.

Real Android/iPhone 20–30 minute frame time/CPU/GPU/memory/heat tests, device minimum OS selection, 16 KB runtime, Wi-Fi/cellular handover, notch/tablet multi-touch and store SDK/signing compliance remain NOT VERIFIED/BLOCKED. Wall-clock desktop frame intervals are recorded separately from device FPS; early evidence using Godot delta is historical and is not a hardware frame-time claim.
