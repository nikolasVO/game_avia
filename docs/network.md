# Prototype network protocol

Godot 4.7.2 standard ENet/UDP, protocol 3. Dedicated server runs at 30 Hz, inputs at 30 Hz and snapshots at 15 Hz. Separate reliable event/admission channel 0, unreliable ordered control channel 1, unreliable ordered state channel 2. A server tick applies at most one current control state per player, regardless of packet count; no client delta/position/score RPC exists. Inputs expire after 0.5 s, peer is removed after 10 s without controls; unauthenticated peers expire after 5 s. Public and private rooms have 16 seats, modes are server-bound. 32 is not accepted.

DTLS uses Godot's ENetConnection API and certificate validation against `game-avia.local` and the pinned public development certificate. Outgoing DTLS is configured **before** `connect_to_host`; an ENet mesh peer bridges that connection into Godot's RPC API. Server private key is read only from `AVIA_DTLS_KEY` outside Git. The certificate is public development trust material; there is no private key or long-lived user credential in the client. Native Android emulator DTLS admission/flight/rejoin is verified at9412/c192; physical Android and iOS runtime remain NOT VERIFIED. Development trust/rotation is not production certificate management.

Admission: server generates a cryptographic random 24-byte one-use ticket, binds it to the transport peer and requested version/plane/mode/room, expires it after 90 server ticks and consumes it before spawn. Recovery is a reliable, numbered, idempotent action: holding a button cannot repeatedly respawn the plane, and input timeout cannot manufacture a new press. No HTTP/API/model call occurs per game tick. Invalid numeric inputs, coordinate injection, impossible sequence numbers and rate excess are rejected. Object decoding is not enabled. The RPC engine still parses arguments before game validation; a full hostile-packet/fuzz/resource-exhaustion audit remains open.

Snapshots estimate server clock offset with half measured RTT and smoothing; the server never trusts client time. Own aircraft predict the common flight module and replay unacknowledged inputs after authoritative ACK. Remote aircraft buffer eight snapshots, interpolate three ticks behind and extrapolate at most 150 ms. Own visual correction is damped and bounded at 20 m, with hard reset and diagnostic above 25 m. The underlying simulation is always reconciled immediately. Fixed snapshots occupy 84 bytes per aircraft (max 1344 bytes before RPC metadata); MTU fragmentation at 16 peers still needs packet capture assessment.

Real process tests: replay/expired tickets, untrusted certificate and plaintext connections are rejected; NaN/Inf/out-of-range/position/sequence attacks do not move a stationary plane. Local UDP impairment runs retain both clients at RTT 100/200 ms, jitter ±30/50 ms per direction and loss 1%/3%. See `docs/evidence/`. These are emulated conditions, not carrier handover. Snapshot corrections are measured, not claimed invisible.

Known Godot diagnostic: valid clients departing a DTLS server can cause `TLS handshake error: -30464` (`-0x7700`) after the departure event. Tests record it separately from functional success. Plaintext/wrong-trust negative tests also intentionally cause TLS error logs. Do not hide these logs or claim the transport fully release-ready. External Mac → Thunder UDP echo failed; the public SSH TCP endpoint proves no UDP mapping. No TCP tunnel is described as UDP.

Godot4.7.2 `create_server` forwards its channel argument as incoming bandwidth. Explicit `host.bandwidth_limit(0,0)` and `host.channel_limit(6)` restore intended behavior; ENet congestion policy and application rate limits remain active. Real throttle limit1/32→32/32 and per-packet delivery/rejection evidence are in `enet-bandwidth-defect.md` and `continuation-protocol-final.json`. Nine real scenarios include150 accepted peaceful fire inputs with zero emitted shots, plus actual replay/expiry receipt. Missing packets fail delivery checks; they are never inferred rejected.

Background closes the transport and clears prediction/controls/visuals. Return offers a new server admission from the menu; no old client position is restored on trust. Both desktop lifecycle checks and actual Android Home/resume/rejoin passed. Fresh Mac→Thunder UDP24567 afterc192 deployment still fails; local and external results are kept separate.
